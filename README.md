# ระบบประเมินผลการดำเนินงาน คปสอ. ปีงบประมาณ 2570

เว็บสถิต (GitHub Pages) + ฐานข้อมูล/ล็อกอิน (Supabase) สำหรับทดสอบระบบประเมิน

**แนวคิด:** ประเมินแบบ 60/40 เหมือนเดิม — กลุ่มงานเพิ่ม “ประเด็นที่จะประเมิน” เอง และให้คะแนน PDCA 1–5 ครบ 9 อำเภอ ส่วนแอดมินเป็นผู้กรอก KPI 60% และกำหนดชื่อผู้ใช้/รหัสผ่านให้แต่ละกลุ่ม แต่ละกลุ่มเห็นและแก้ได้เฉพาะของตัวเอง (บังคับด้วย Row Level Security)

---

## โครงสร้างไฟล์
```
index.html          หน้าเว็บหลัก (login + แอป)
app.js              ตรรกะทั้งหมด
styles.css          รูปแบบหน้าตา
config.js           << แก้ค่าตรงนี้ (Supabase URL + key)
supabase_setup.sql  สคริปต์สร้างฐานข้อมูล + สิทธิ์ + 15 กลุ่ม
.nojekyll           ให้ GitHub Pages เสิร์ฟไฟล์ตรง ๆ
```

---

## ขั้นตอนติดตั้ง (ครั้งเดียว ~15 นาที)

### 1) สร้างโปรเจค Supabase
1. ไปที่ https://supabase.com → สมัคร/เข้าสู่ระบบ → **New project** (เลือก Region Singapore)
2. ตั้งรหัสผ่านฐานข้อมูล (จดไว้) → รอสร้างเสร็จ

### 2) สร้างฐานข้อมูล
1. เมนูซ้าย **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase_setup.sql` คัดลอกทั้งหมดไปวาง → กด **Run**
3. จะได้ตาราง + สิทธิ์ + 15 กลุ่มงานอัตโนมัติ

### 3) สร้างบัญชีผู้ใช้ (แอดมินเป็นผู้กำหนด)
1. เมนูซ้าย **Authentication → Users → Add user**
2. เพิ่มทีละบัญชี (ติ๊ก **Auto Confirm User** ทุกครั้ง):
   - แอดมิน: email `admin@cup.local` + รหัสผ่าน
   - กลุ่ม 1–15: email `group1@cup.local` … `group15@cup.local` + รหัสผ่าน
   - *(ชื่อผู้ใช้ที่แจกให้กลุ่ม = `group1`…`group15`, แอดมิน = `admin` — ระบบจะเติม `@cup.local` ให้เอง)*
3. กลับไป **SQL Editor** รัน 2 คำสั่งท้ายไฟล์ `supabase_setup.sql` อีกครั้ง (ส่วน “ผูกบัญชีเข้ากับกลุ่ม/บทบาท”) เพื่อผูกบัญชีที่เพิ่งสร้างเข้ากับกลุ่ม
   *(ถ้ารันทั้งไฟล์ซ้ำก็ได้ ไม่กระทบข้อมูลเดิม)*

### 4) ใส่ค่าเชื่อม Supabase ลงในเว็บ
1. Supabase → **Project Settings → API**
2. คัดลอก **Project URL** และ **anon public key**
3. เปิด `config.js` วางทับค่า `SUPABASE_URL` และ `SUPABASE_ANON_KEY`

### 5) ขึ้น GitHub Pages
1. สร้าง repo ใหม่บน GitHub แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (หรือ `git push`)
2. repo → **Settings → Pages** → Source = **Deploy from a branch** → Branch = `main` / `/root` → Save
3. รอสักครู่ จะได้ลิงก์ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/` → เปิดใช้งานได้เลย

## วิธีใช้งาน
**แอดมิน** (`admin`): แท็บ *บัญชี/กลุ่มงาน* (ดู/ล็อกประเด็น/ผู้ประสานงาน) · *กรอก KPI 60%* · *ผลรวม 60/40* (+ ดาวน์โหลด CSV)

**กลุ่มงาน** (`group1`…): แท็บ *ประเด็นการประเมิน* (เพิ่มเอง) · *ให้คะแนน PDCA* (1–5 × 9 อำเภอ บันทึกอัตโนมัติ) · *ผลของกลุ่ม* · *ข้อมูลกลุ่ม*

**ลำดับการใช้งานที่แนะนำ:** เปิดให้กลุ่มเพิ่มประเด็น → แอดมินกด **ล็อก** ทุกกลุ่ม → กลุ่มให้คะแนน PDCA → แอดมินกรอก KPI → ดูผลรวม 60/40

---

## สูตรคำนวณ
- S ของประเด็น (ต่ออำเภอ) = 15 × ค่าเฉลี่ย(P,D,C,A,R) + 25  *(ต้องกรอกครบ 5 ช่อง)*
- S ของกลุ่ม (ต่ออำเภอ) = ค่าเฉลี่ย S ของทุกประเด็นในกลุ่ม
- ส่วนที่ 2 (ต่ออำเภอ) = ค่าเฉลี่ย S ของทุกกลุ่มที่ประเมิน
- คะแนนรวม = KPI% × 60% + PDCA% × 40%  *(ปรับน้ำหนักได้ในแท็บ KPI)*
- ระดับ: ดีเยี่ยม ≥90 · ดีมาก 80–89.99 · ดี 50–79.99 · ต้องปรับปรุง <50

## หมายเหตุ
- ชื่อ 9 อำเภอ / 15 กลุ่มงาน แก้ได้ (อำเภอใน `app.js` ตัวแปร `DISTRICTS`; กลุ่มในตาราง `groups`)
- โดเมน email (`cup.local`) ใช้เพื่อ login ภายในเท่านั้น ไม่ต้องเป็นอีเมลจริง — เปลี่ยนได้ที่ `LOGIN_DOMAIN` ใน `config.js` (ต้องตรงกับที่สร้างใน Supabase)
- anon key เป็น public key ใส่ในเว็บได้ตามปกติ ความปลอดภัยคุมด้วย RLS ฝั่งฐานข้อมูล
- เป็นระบบเพื่อ “ทดสอบ” — ก่อนใช้จริงควรทดสอบ login หลายบัญชีและตรวจสูตรให้ครบ
